# ADR-0003. Set-Cookie 는 파싱·재조립 대신 오프셋 splice 로 수정한다

## 맥락

기존 구현은 `set-cookie-parser` 로 객체를 만든 뒤 프레임워크 API 로 다시 구웠다.
이 방식은 파서가 모르는 속성을 전부 떨군다. `Partitioned`(CHIPS), `Priority` 가 실제로 사라진다.

## 결정

원문을 한 번 스캔해 각 속성의 `[start, end)` 오프셋과 소문자 이름만 인덱싱한다.
수정은 편집 목록을 만들어 **뒤에서 앞으로** 적용해 오프셋이 어긋나지 않게 한다.
손대는 속성은 `Domain`, `Secure`, `SameSite`, `Path` 넷으로 고정한다.

## 근거

- 코드가 모르는 속성은 존재 자체를 모르므로 자동으로 보존된다. 앞으로 추가될 속성에도 안전하다.
- 값 문자열을 다시 인용부호로 감싸거나 인코딩하는 실수가 원천적으로 불가능하다.
- 외부 의존성이 사라져 코어 의존성 0 목표를 지킨다. 쪼개기와 이름 추출은 자체 구현이 짧다.

## 결과

문자열 스캐너를 직접 관리해야 한다. 따옴표 값 안의 세미콜론 처리 등 엣지 케이스를
단위 테스트로 고정한다.
